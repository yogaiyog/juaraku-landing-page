# Sales Landing Page Planning
## Purpose

This landing page is **not** for cold traffic.

It is designed specifically for **parents who have already attended a Trial Class** and are currently in the sales follow-up process.

The primary goal is to increase the closing rate by answering the most common questions, building trust, and reinforcing the value of joining JuaraKu.

---

# Target Audience

Primary

- Parents who have completed a Trial Class.
- Parents who are considering enrollment.
- Parents who have spoken with the sales team.

Secondary

- Sales team
- Mentor
- Customer Success

---

# Main Goals

- Increase Trial → Paid conversion.
- Reduce parent hesitation.
- Build trust in JuaraKu.
- Show long-term learning roadmap.
- Encourage immediate enrollment.

# Personalized Assessment Flow (Implemented)

This page supports dynamic personalization. Before entering the Sales Landing Page, the admin or sales team completes a simple assessment form.

```text
Admin / Sales
        │
        ▼
Input Student Name
        │
        ▼
Input Assessment Score
- Learning Speed
- Concept Understanding
- Problem Solving
- Fokus
        │
        ▼
Generate Assessment
        │
        ▼
Open Personalized Landing Page
(/trial?name=...&speed=...&concept=...&problem=...)
        │
        ▼
Section 2 Automatically Displays Personalized Assessment
```

## Assessment Input Form

### Student Information

- Student Name (Required)

### Assessment

Each scored 1–5:

- Learning Speed
- Concept Understanding
- Problem Solving
- Fokus

Button

> Generate Landing Page

## Generated Data

```ts
{
  studentName: "Raka",

  assessment: {
    speed: 5,
    conceptUnderstanding: 5,
    problemSolving: 2,
    focus: 4
  }
}
```

The assessment generator then produces a personalized feedback paragraph using the AI assessment rules (see `assesment-plan.md`).

> **Implementation note:** the generator is a built-in **rule engine** (offline, no API key) that composes the assessment from score-bucketed sentence banks with seeded variation — see `lib/assessment/generator.ts`. An LLM-powered version is a future enhancement.

## Rendering Behavior

Section 2 must render dynamically.

Display:

- Student Name
- Generated Assessment
- Strengths
- Growth Areas
- Encouraging Conclusion

The content should update automatically whenever the admin changes the assessment values.

No manual editing should be required.
